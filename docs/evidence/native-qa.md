# Actual OmO-backed local QA (2026-09-24)

Environment: Windows x64, Bun 1.4.0, pinned OmO Native beta.88 / Senpi 2026.9.23-5 with two project-local patches. LM Studio already had `qwen3.5-9b-uncensored-hauhaucs-aggressive` loaded, type VLM, `tool_use`, **loaded context 69,376**; no model settings or global OmO were changed. All model inputs below were public fixture prompts; user clipboard and pre-existing processes were not accessed. Disposable workspace/profile removed after each run. `doctor --json` returned the actual model ID, loaded context and canonical fixture root without writing state.

Before the allowlist, the same OmO call used 19,669 total tokens. |

Manual coverage gaps: real interactive ConPTY/TUI rendering and native Alt+V OS clipboard paste were **not captured**. A local `node-pty` build attempt failed because Visual Studio's Spectre-mitigated libraries are unavailable; no dev dependency was retained. The current clipboard was never overwritten, so an actual pasted image is unverified; explicit public `--image` vision succeeded. A direct multi-turn *live* RPC attempt timed out on its first greeting while real one-shot sessions and deterministic native RPC succeeded; the six-turn real model evidence uses persisted `--session` instead. Native TUI, `/new`, `/resume`, and Alt+V are upstream Senpi documented surfaces, not a fabricated mini editor. Do not claim a rendered TUI screenshot or Windows clipboard regression as passed on this evidence.

A temporary OmO LSP daemon spawned by one early coding probe retained a handle to its disposable workspace after the task; the **probe-owned** PID 55712 was identified from its command line, stopped, and its temporary workspace removed. OmO LSP was then disabled for this profile. No pre-existing user OmO or omo-mini process was stopped.
