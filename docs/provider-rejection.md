# Pinned provider-request rejection patch

This project patches MIT-licensed `@code-yeongyu/senpi@2026.9.23-5` (copyright its upstream contributors; license in its installed `LICENSE`) and `omo-ai@5.0.0-0.beta.88` using Bun's `patchedDependencies`. No OmO SUL code is relicensed. Apply with `bun install --frozen-lockfile` from this project; do not install or patch the global engine.

The two patch files are `patches/@code-yeongyu%2Fsenpi@2026.9.23-5.patch` (26 Senpi files) and `patches/omo-ai@5.0.0-0.beta.88.patch` (4 omo-ai files); Bun applies them to the project-local packages at install. The provider-request rejection described below is one part of them; [Patch contents](#patch-contents) lists every patched file and why it changes. Most changes run only when `OMO_MINI_LOCAL_PROFILE` is `"1"` or another `OMO_MINI_*` variable set by the omo-mini launcher is present; the others are marked *all profiles*.

Senpi's `before_provider_request` previously logged and ignored *all* handler exceptions, including the local profile's budget rejection. The project patch makes a handler's explicit `{ action: "reject", reason: string }` result throw outside that exception logger, so the pending `onPayload` rejects before the provider transport. Ordinary thrown extension errors still log and are ignored. The omo-ai launcher normally prefers Senpi's prelinked bundle, which contains its own unpatched runner; the second patch selects Senpi's unbundled `dist/cli.js` to ensure this patch is actually executed. The profile extension converts only `MiniError` policy failures into the explicit result.

`bun test tests/provider-rejection.test.ts` drives the real CLI against a loopback HTTP model endpoint. A valid request whose serialized UTF-8 size exceeds the removed byte proxy reaches the local provider. A mismatched provider still produces zero generation requests. Native Senpi owns context usage accounting, automatic compaction and bounded recovery from actual provider overflow; the local identity gate must not turn a JSON byte estimate into a terminal context rejection. The sentinel is an intentional policy rejection result, not an error-name or message matching heuristic.

Native turns have no fixed provider-request count limit: successful tool work can continue beyond 12 requests. Five consecutive tool errors still reject the next provider request, and repeatedly retrying an identical failed action still terminates the turn. New user input resets these guards. `tests/native-turn-budget.test.ts` covers completion after 16 successful reads, the consecutive-error stop, and recovery on the next user turn; `tests/native-repeat-failure.test.ts` and `tests/native-cancel.test.ts` cover failed-action loops and user cancellation. A model that keeps making successful but unhelpful calls can be cancelled through the native interface.

The earlier mini profile disabled OmO LSP after an edit probe left a detached daemon holding a disposable Windows workspace open. That was a historical workaround, not the current Native contract. The current launcher does not pass `--omo-senpi-lsp-disabled`, and the current pinned Senpi patch does not add the old profile-only LSP loader guard. Native LSP tools remain exposed; `tests/native-lsp.test.ts` checks the extension-loader flags, not successful diagnostics against an installed language server. Actual LSP execution requires a working server/configuration and its own verification. These changes do not relax the fail-closed local-model provider check described above.

## Patch contents

Paths are relative to each package root. Items not marked *all profiles* take effect only in the omo-mini local profile.

Senpi (`@code-yeongyu/senpi@2026.9.23-5`):
- Provider-request policy: `dist/core/extensions/runner.js` and `dist/core/extensions/types.d.ts` add the rejection sentinel described above (*all profiles*). In the profile the runner also passes the request's resolved model and headers to `before_provider_request` handlers, and `dist/core/extensions/builtin/compaction/speculative-summary.js` supplies them for compaction summary requests, so the local identity gate can check a summary request the same way as an agent turn.
- Local model lifecycle: LM Studio loads a model when it is selected, so a downloaded catalog entry is not yet usable for inference. `dist/core/sdk.js` starts with no model while none is loaded and adds `ls` and `find` to the default tools. `dist/core/agent-session.js` rejects prompts until a model is loaded, loads the model through the omo-mini lifecycle module on `/model` selection or automatic fallback, re-registers the local provider with the loaded context size, and rolls back on failure; automatic fallback follows only the approved local chain in `OMO_MINI_LOCAL_FALLBACK`, never global, project or built-in cloud chains. `dist/modes/interactive/components/model-selector.js` lists the local catalog, `dist/modes/rpc/connection-handler.js` answers `set_model` asynchronously so an abort is not queued behind a long load, and `dist/modes/interactive/interactive-mode.js` shows a loading status. `dist/core/retry-fallback/controller.js` (*all profiles*) records the model actually active after a fallback switch, because admission can resolve a downloaded key to a new loaded instance ID. `dist/core/sdk.js` and `dist/core/sdk.d.ts` also forward the `fallbackNow` clock option (*all profiles*) for deterministic cooldown tests.
- Identity: `dist/cli.js`, `dist/main.js`, `dist/core/project-trust.js` and `dist/modes/interactive/interactive-mode.js` show `omo-mini` in the process and terminal titles, loading label, trust prompt and startup header, hide the `omo-native` footer badge, and take the resume hint from `OMO_MINI_RESUME_HINT`, so a Mini session never points the user at their own OmO Native.
- Working folder and offline flag: `dist/core/extensions/builtin/hooks/trust-storage.js` no longer creates `<cwd>/.omo` just by reading project hook state. The profile sets `PI_OFFLINE=1` to stop remote catalog and startup fetches; `dist/utils/tools-manager.js` keeps on-demand `fd`/`rg` installation working under that flag.
- Tool output: `dist/core/tools/grep/index.js` and `dist/core/tools/grep/format.js` mark a capped grep result with a "Match limit reached" note, `limitReached=true` and the full `totalMatches` count, so a truncated result does not read as complete. `dist/core/extensions/builtin/terminal/extension.js` exposes the background bash session tools only inside `eval`, the only place the background bash they address can be started. `node_modules/@code-yeongyu/senpi-codemode/src/kernels/js/display-image.js` shows a text-only tool result as plain lines instead of one column-clamped JSON line.
- Compaction: `dist/core/extensions/builtin/compaction/deterministic-fallback.js` adds the latest user request (up to 4096 bytes) to the deterministic fallback checkpoint. Without it, a first fallback leaves the model no task once the user turn falls before the kept boundary.
- Peer threads (*all profiles*, opt-in): `dist/modes/rpc/rpc-client.js` and `dist/modes/rpc/rpc-client.d.ts` add `requestSession` for commands addressed to one session; `dist/modes/rpc/rpc-types.d.ts` and `dist/modes/rpc/session-command-router.js` add `close_session` with `if_idle`, which returns `session_busy` unless exactly one attachment owns an idle session. omo-mini's peer-thread host uses both, so moving a peer does not abort an active turn, a background task or another client's session.
- Windows clipboard (*all profiles*): `dist/utils/clipboard-image.js` and `dist/utils/clipboard-image.d.ts` read a single PNG/JPEG file copied in Explorer, which puts a file list rather than image data on the clipboard, when no image data is present. The file is limited to 2 MiB and 16 megapixels, re-encoded as PNG, and the clipboard is not changed.

omo-ai (`omo-ai@5.0.0-0.beta.88`):
- `bin/lib/package-paths.js` (*all profiles*): always starts Senpi's unbundled `dist/cli.js`, as explained above.
- `bin/lib/launcher.js`: skips the omo-ai beta banner and `omo setup` hint on interactive start, since omo-mini runs the engine under its own identity.
- `plugin/extensions/omo.js` and `plugin/extensions/omo-task.js` are minified, so each patch replaces the file's single code line. In both, the project `.omo` config lookup stops at `OMO_MINI_NATIVE_HOME`, the user's real home directory: the profile points `HOME` and `USERPROFILE` at an isolated home, so without this boundary the upward walk from a project could reach the user's own OmO config. `omo.js` applies the same boundary to the config-migration directory walk, skips the memory `post-commit` mirror push unless `OMO_MINI_NATIVE_MEMORY_SYNC=1`, and runs thread tools on the peer host module named by `OMO_MINI_PEER_BRIDGE` instead of the shared Senpi thread host, refusing to start without it; its `thread_create` passes the caller's current model to the host's `openSession` (*all profiles*). `omo-task.js` (*all profiles*) refreshes the task runtime's session context on each `task` call and does not register the scheduler `workpool` tool in a task RPC child that runs as a workpool worker.
