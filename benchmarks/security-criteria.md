## Evidence schema and honest limits

`product-preflight.json` records one read-only point-in-time product/benchmark manifest, optional module presence and bundled-resource root hashes; it never starts Native/model inference and does not replace the per-suite freeze checks. `{phase}-metrics.json`: `schemaVersion: 2`, `complete`, `cleanup` (pending/succeeded/retained/failed, scratch root and failure detail), `authorizationScope` (exact common model-visible prompt suffix), `sourceFreezeEpoch` (explicit operator ID, ISO start, full effective product hash, pre-fix baseline flag), `benchmarkManifest` (version, digest, per-file hashes), `fixtureHash`, `model`, `endpoint`, `loadedContext`, `deadlineMs`, `cli`, `cliSha256`, `productFingerprint`, `productFiles[]` (relative file name and SHA-256), `rows[]`. The product root is the checkout containing the invoked `dist/cli.js`; required dynamic modules include `dist/extension.js`, reflection modules and the patched Native permission runtime. `dist/model-admission.js` is fingerprinted when present and recorded explicitly as absent when not shipped: it is not loaded by an already-loaded-model baseline, while `/model` direct-load remains a separate acceptance goal. Missing **required loaded** modules fail preflight. Every row includes `id`, `kind`, exact `task`, common `authorizationScope` and `invocation`, source fixture hashes before/after, `exit`, `timedOut`, `wallMs`, `completionReason`, `terminalObserved`, raw status, `toolCalls`, paired `toolPairs[]`, `nestedToolCalls[]`, `validatedPublicTest` (toolCallId, name, args, result), `toolErrors`, `expectedReproFailures`, `unexpectedToolErrors`, `evidenceProvenance`, `processTreeCleanup` (taskkill /T PID list plus event-based Windows process-exit and tasklist check on a timeout), `transportSchemaErrors`, `repeatedUnchangedFailedAction`, `unparsableLines`, observed outbound `requestBytes[]`, `forwardedRoutes[]`, provider-reported `providerUsage[]`, observed `generationRequests[]` (only request JSON parameters actually present, not inferred defaults), `productFingerprintBefore`/`productFingerprintAfter`, independent `oracle`, `passed`, `failureClass`, and raw artifact filenames. `promptAck`, `approvals[]` (request id, tool, decision, reason), `expectedApprovalCount`, `permissionBlockedCount`, and `approvedResourceReads[]` (canonical path, installed package-relative origin, SHA-256 of file or root, full product fingerprint) record the Native RPC permission boundary; an explicit safety denial is `permission_blocked`, not a model-security correctness error or a transport failure. `{phase}-{ID}-events.jsonl` is the actual Native CLI stream with tool calls and results; stderr is separately saved. `--compare` emits per-suite pass, latency, calls, errors, request byte arrays, **all observed per-request** generation settings and effective product hashes. It compares the observed fixed settings of the **first** generation request per task between baseline/candidate (later requests are captured but not asserted equal because tool-call trajectories can diverge); byte sizes are never converted into tokens. Latency is process wall time; bytes are observed HTTP request body sizes, **not tokens**. Provider usage is labeled provider-reported and may be absent. Do not claim speedup from these eight local cases as universal.

**Native eval-to-bash contract (frozen before v7 baseline):** In the active Native profile direct `bash` only returns a routing hint. To execute a targeted public fixture test, the model must call Native `eval` with `language: "js"` and one cell of the verified Native form `display(await tool.bash({ command: "bun test public.test.ts -t SQL" }));` (the equivalent `print(await tool.bash({"command":"bun test public.test.ts -t SQL"}))` is also accepted) (replace `SQL` with the task-specific `document`, `shell`, `private`, `audit`, or `retry` label). The accepted grammar is one `print` or `display` of one awaited `tool.NAME({ ... })` call, optional harmless whitespace and one trailing semicolon, with `NAME` in `read`, `grep`, `find`, `ls`, `write`, `edit`, with the actual Native tool schema keys. The TypeScript AST must contain exactly that one expression; its argument is an object containing static primitive/object/array literal data with identifier or string-literal keys (bare keys are supported). Type arguments, optional or computed access, spread, getters, methods, executable values, imports, ambient APIs, comments, extra statements, duplicate/unknown keys and dynamic interpolation are rejected. Escaped literal strings are decoded before command/path validation. The actual published Native edit schema is `{ path, edits: [{ oldText, newText }] }`; legacy top-level `oldText/newText` is not admitted. Native bash accepts `command` with optional timeout seconds, which this suite limits to 1..30; `grep`/`find`/`ls` may omit `path` and then resolve only against the disposable fixture root. Runtime permission validation applies the same canonical fixture/resource paths, exact targeted test command, and permitted nested argument keys. A direct-bash permission is denied unless matched to a pending approved eval. The score requires `eval` result `details.toolCallCount === 1`, the nested tool name/args, and an actual successful targeted `bun test` result preview (`(pass)` and `0 fail`) for coding cases. A direct bash routing hint or model's prose claim never counts as a test. Expected red tests are tracked separately; they do not waive subsequent green validation. The offline native probes include the verified display/bare-key/semicolon form and the print/quoted-key form, using actual `src/cli.ts rpc` and eval->`tool.bash` against a disposable local test with **synthetic SSE model transport**; it verifies the Native tool result `details.toolCalls[0]` reports an executed successful test. A second real-Native probe calls direct `bash` and observes a `Tool bash not found ... Run bash inside an eval cell` routing hint with `isError: true` and no test output. Neither probe measures Qwen performance. The real Qwen benchmark remains paused until integrated-ready.

**Run-scoped bundled-resource read policy:** Before a model run, canonicalize the two verified installed public roots `node_modules/omo-ai/plugin/skills/` and `node_modules/omo-ai/plugin/runtime/agent-toolkit-sdk/` within the effective product checkout. Fingerprint **all** their shipped reference files, including Markdown and scripts, along with the installed Native runtime. `read`/`list` may receive `Allow once` only for an exact cataloged resource; `external_directory` requires a cataloged directory and every explicit pattern to be cataloged, plus a matching pending Native `tool_execution_start` for `read`, `grep`, `find`, or `ls`, or an already-approved parsed read/search-only eval cell on that path. Resource edits, opaque eval/MCP, app source outside these two installed roots, the real home, benchmark code and hidden oracles remain denied. Record every approved resource separately from ordinary fixture approvals. This approval is a single Native permission reply, not a global allow rule. A changed resource changes the product fingerprint and aborts the suite. If Native presents no pending typed read/search event, deny and report `permission_blocked` rather than guessing from a pathname; ops' actual sentinel completion remains a separate preflight. The runner does not expose fixtures/oracles through this policy.

**Scope and observation limit:** No OS sandbox is a prerequisite for starting these authorized local benchmark runs. The runner uses disposable owned fixtures and only loopback targets, responds to each Native permission select with an explicit `Allow once` for a visible in-root file action, a narrowly parsed tool-only eval targeted fixture test or file operation, or the cataloged installed read-only resources above; it sends `Deny` for out-of-root or opaque actions. Do not bypass permissions globally. Typed `tool_search` is permitted for bounded metadata queries (including optional `source`/`group`) but does not execute returned tools. A normal Native eval `display(await tool_schema("read"))` or the equivalent `print` is approved only for one statically parsed, displayed schema lookup with a literal name in the fixed set of Native file, bash, search and LSP tool names; it requires `language: "js"`, `code` and nonblank `summary`. It never counts as an executed public test or read/search provenance. Arbitrary eval code, task/child delegation, LSP actions, terminal sessions and MCP execution remain denied for this suite (product eval stays enabled); rejected requests are reported as `permission_blocked`; this is an observable boundary/runner limitation for the Native owner to review, not evidence of a tool-transport defect and not a reason to halt unrelated cases. The runner observes its proxy's model requests and Native RPC events; it does **not** claim kernel-level write confinement, exhaustive process-tree activity, or universal absence of other network egress. No OS sandbox product is requested. Do not unload the active model.

Before final scratch removal the runner reads only this suite's per-task Native daemon state homes. For a live owner it requires matching pid/endpoint files, the installed product runtime CLI, a process creation time inside this suite, the exact executable/daemon command line and an authenticated `omo/ping` matching the owner PID, nonce, start time and endpoint; then sends the daemon's registered `SIGTERM` and uses the OS process-exit handle and a second process identity check. Cleanly exited daemons have no owner/pid/endpoint metadata. Unknown, conflicting or unreachable live ownership is a cleanup failure: retain scratch, record partial exit proofs and `complete:false`; never signal unrelated or unattested PIDs. `cleanup.ownedDaemons[]` records task, owner identity, process command/start identity, shutdown signal and verified absence. On timeout the runner calls Windows `taskkill /PID ... /T /F`, waits for the direct child exit, waits on each reported process exit handle with a bounded deadline, checks that reported child/descendant PIDs are absent and records the evidence. Failure to prove cleanup aborts the suite and retains scratch for diagnosis; no next case starts. Scoring/evidence exceptions record a failed row and partial suite (`complete:false`), keep raw RPC logs, and stop. The runner does not claim to detect a detached process that escaped the reported Windows process tree.
