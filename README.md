# omo-mini 0.2.2

**An independent local-model profile of real OmO Native**, not a separate read-only agent. The `omo-mini` launcher starts pinned `omo-ai@5.0.0-0.beta.88`, its OmO plugin, and pinned Senpi `2026.9.23-5`. A small explicit extension adapts the prompt, tool output and error feedback to the selected local model. Within each user turn, an observed failed native tool action cannot execute again with identical tool arguments; the agent can try a different action or must stop after bounded blocked choices. Successful coding actions and new user turns permit justified retries. The native OmO/Senpi TUI, coding tools, project instructions, permission system, session tree and image handling remain upstream-owned.

## Install and use

Requires Bun 1.4+, Node 24+, and an eligible downloaded tool-capable chat model in local LM Studio (default `http://127.0.0.1:1234/v1`). LM Studio's `/api/v1/models` is needed to list downloaded models and start the interactive picker with nothing loaded; the legacy `/api/v0/models` route supports selection only from already-loaded instances. Inference needs a loaded instance with a reported effective context. Image inference also needs a local vision-capable instance. Global OmO settings are not imported.

```sh
bun install --frozen-lockfile  # applies the two pinned project-local upstream patches
bun run typecheck
bun test
bun run build
bun link                   # optional: register this repo's omo-mini command
omo-mini doctor --json
omo-mini --root /path/to/workspace                # OmO native interactive TUI
omo-mini run --root fixtures/tiny --task 'Read src/ledger.ts and explain invoiceTotal' --json
omo-mini run --root fixtures/tiny --image image.png --task 'Transcribe this image' --json
omo-mini run --root fixtures/tiny --session my-task --task 'Continue the work' --json
```

The default state is `~/.omo-mini/{home,agent,sessions}`; override with `--state-dir PATH`. The process's `HOME`, `USERPROFILE`, OmO/Senpi agent directories, and session directory point there, so installed `~/.omo` settings, cloud-model credentials and sessions are not adopted. `doctor` discovers a **loaded** local model and reports its ID, effective loaded context and canonical workspace without creating state; it does not load one. `--base-url` accepts only a loopback HTTP `/v1` endpoint. With a downloaded eligible model but no loaded instance, interactive `omo-mini` starts without inference: choose the downloaded model using Native `/model` to load it and inspect its effective context before chatting. `omo-mini rpc` likewise can start unloaded for integrations. An unqualified `run` needs a loaded instance; `run --model ID` may load the named downloaded model if necessary. For interactive/RPC, `--model ID` selects a downloaded or loaded identity at launch but does **not** itself load an unloaded instance; use `/model` (or its Native RPC equivalent) to load it. `doctor --model ID` remains loaded-only. A legacy v0-only LM Studio server cannot start an unloaded picker. The `run --session NAME` argument is a safe name under the mini session directory; ordinary `run` also uses upstream sessions. Interactive `/new` creates a distinct session; `/resume` opens existing project sessions. At narrow terminal widths, `/local-profile` displays the full canonical workspace root and selected local model in wrapped lines (the footer itself can ellipsize). `omo-mini rpc` exposes OmO's native JSONL RPC over standard input/output for integrations.

Native retains coding tools, including read, edit and write; with codemode active, shell and search tools run through `eval` rather than direct model calls. The model catalog stays local while Native skills, delegation, LSP and extension tools remain available, subject to permissions and service prerequisites. `workspace` is the default native permission preset; `--permission ask|read-only|workspace` selects another. Destructive `rm *` and `Remove-Item *` receive explicit deny rules. **Permissions are confirmation policy, not an OS sandbox**; approve only trusted workspaces/commands. Project context files (AGENTS.md/CLAUDE.md) remain enabled. Project-local executable resources remain subject to Native trust; approve only the intended workspace. Cloud-model fallback and inherited cloud-model credentials are disabled; bundled Context7 and grep.app MCP services and local `_ast_grep` remain exposed. Optional service keys (`CONTEXT7_API_KEY` and `GREP_APP_API_KEY`) may be passed separately from model credentials; actual remote calls need network access and, where required, service credentials. A listed or connecting MCP is not evidence of a successful call. LSP actions need an available language server; web/browser and image/VLM actions have their own network, installation, credential or loaded local-vision-model prerequisites. Local-only provider and model identity are checked again at the *effective provider request*, with an intentional fail-closed rejection before HTTP. Native tools are not sandboxed or reimplemented here.

Automatic onboarding and the Native telemetry plugin component are disabled by default; the explicit `/skill:onboarding` remains callable. Pass `--native-telemetry` with an interactive, `run` or `rpc` session to enable Native's telemetry component explicitly; `doctor` does not accept this flag. This leaves the isolated profile and local inference guard in place. The flag is a component opt-in, not a claim that every engine telemetry path was audited or that opting in makes cloud-model inference available.

On Windows, the native TUI uses **Alt+V** for image or text clipboard paste. Ctrl+V works only when the terminal forwards it; omo-mini does not seize the terminal shortcut. The explicit `--image` option sends actual image pixels inside the model request. The user clipboard is never modified by omo-mini's setup or tests. The upstream TUI supplies multiline editor, status and session controls; no custom readline UI runs here. `run --json` writes native OmO JSONL events; if OmO's admission fails before any event or a turn ends empty/length/error, it adds an `omo_mini_status` JSON object and exits nonzero. Interactive abnormal endings are shown via extension notifications.

### Local memory and ongoing work

The state directory contains `memory/`, managed by the actual OmO Native memory subsystem. The default is `~/.omo-mini/memory`: only omo-mini conversations and lessons accumulate here; existing OmO Native memory data is neither imported nor shared. Reflection, facts extraction, dream maintenance, nudges, search, recall and the native prompt cache are enabled. Reflection reviews observed mistakes and successful corrections, commits durable lessons through Native's memory worktree, and projects committed `system/` memory into later conversations. It can also maintain reusable skills. The local prompt preserves Native's complete memory projection. Callable skills from this mini memory identity are listed in the first main-model request with Native names, descriptions and load paths; skills from other identities or the normal OmO profile remain excluded.

All memory workers use the loaded `omo-mini-local` model through the pinned `quick` category. Automatic mirror sync is off by default. `--native-memory-sync` explicitly allows the existing Native memory repository hook to push commits from this Mini-only identity when a mirror URL was already configured in that repository; it requires `workspace` permission and refuses a state directory overlapping global OmO memory. Mini does not create accounts or configure a mirror. `/memory-repository set <url>` and `/memfs sync` are separate explicit Native actions that can contact a remote, independent of this automatic opt-in; use them only deliberately. No successful remote push is claimed. Recall uses one concurrent wake and at most 16K tokens; the memory compilation warning budget scales with the loaded context, up to 8K tokens. Read-only mode disables automatic reflection, facts and dream writers. Supported project memory tuning is allowed; conflicting identity, sync or worker-model settings are rejected; project `memory.sync.remote` cannot redirect Mini to another repository. Native memory remains isolated from the normal OmO profile.

Native model fallback stays off unless `--native-local-fallback ID` names an eligible downloaded local model. Repeat the flag for an ordered local ladder. Native retry/fallback handles the turn; each automatic fallback and revert must load and admit its effective local instance before inference. The last manually selected default remains saved while the active fallback changes. The unloaded TUI still requires `/model` before inference. Native cloud-family recommended selection remains disabled.

Mini reflection workers use structured `reflection_input` pages and an exact-path `reflection_commit` tool alongside Native file tools. This avoids shell scripts for parsing transcripts and keeps temporary files out of commits. Native still owns validation, merging and cursor advancement; dream keeps its original workflow. See [reflection repair verification](docs/evidence/reflection-tools-2026-09-25.md). An existing mini session can load the rebuilt adapter with `/reload` before its next `/reflect`.

Use `/memfs init` to initialize a project immediately, `/memory` or `/memfs status` to inspect it, `/reflect` to review recent conversations now, `/dream` for maintenance, and `/recompile` to invalidate the native prompt cache. Automatic reflection retains Native's 25-step and compaction triggers. Use the native `memory` tool with `command: "delete"` for an explicitly selected file to forget it. Durable learning depends on the local model's assessment; Native does not persist every failed call as a permanent rule.

`/new` starts a fresh task while retaining the project's committed memory; `/resume` selects an earlier task. Native goal/todo tools and the session-only work checkpoint preserve the current task and observed tool results through compaction. Intended actions are not execution evidence. File-tool failures remain blocked across unrelated successful shell commands; a changed target fingerprint permits retry. Successful coding actions can still release failed shell actions for repair verification, while memory/todo bookkeeping cannot.

Earlier bounded single-result checkpoints remain readable. If a derived checkpoint is invalid, its data is omitted with a warning while the selected conversation remains available; verify actual results before treating any plan as completed work. A different-project session remains blocked.

The local harness compares successful inspection results as well as errors. Two identical observations trigger a temporary recovery notice containing the prior result. For a regular file whose native path and metadata are unchanged, a third identical query is blocked before execution; changing the file permits verification. Shells and directory searches receive advice without this extra hard block, since they may observe changing external state. Three ignored blocks of the same file action terminate that loop honestly; the upstream Native guard still handles other loop patterns. The checks retain original tool-call/result pairs and do not train the model. See [tool-loop hardening verification](docs/evidence/tool-loop-hardening-2026-09-25.md).

When consecutive tool steps repeat substantial reasoning paragraphs, the local extension supplies a brief, temporary instruction to reconsider the latest evidence and choose a supported next action. It preserves the original reasoning and tool results, adds no request-count cutoff, and resets for new user turns and sessions. This can help the model recover from repeated planning; it cannot guarantee correct reasoning. See [reasoning recovery verification](docs/evidence/reasoning-recovery.md).

See [Native memory integration](docs/evidence/native-memory-integration.md) for current QA, [earlier repetition and memory evidence](docs/evidence/repetition-memory.md) for the original guard checks, and the [checkpoint recovery receipt](docs/evidence/checkpoint-recovery.md) for the existing session repair. See [v7c Native gate and limits](docs/evidence/native-v7c-publication.md) for the dated synthetic-test receipt and outstanding live gates.

### Local capacity

The local profile sets model `contextWindow` to LM Studio's effective loaded context and keeps Native tool discovery, compaction and token-based tool-result admission. Its configured output ceiling follows that context instead of a fixed 2048-token limit; native compaction reserve and recent history are set to 4096 each. Serialized request bytes are measurements, not token limits; the endpoint's own context rejection remains authoritative. No tool-call/result pair is manually spliced: native session compaction owns message retention. [Native QA](docs/evidence/native-qa.md) records historical read, edit/write/bash, image and Korean session checks on an already-loaded, vision-capable 69,376-context Qwen; its dated results do not verify this later text-only, 65,536-context model/build. [Native release evidence](docs/evidence/native-release.md) also records dated observations, not a present-build certification. Delegation, MCP services, LSP and skills remain exposed; their catalog presence does not establish that every operation or external service succeeds. Model inference stays on the selected local instance.

Later [native release evidence](docs/evidence/native-release.md) records actual TUI, session, interruption and image-paste observations, including unresolved local-model limitations. The earlier native QA page records what had been verified at that date.

See [THIRD_PARTY.md](THIRD_PARTY.md) and [patch rationale](docs/provider-rejection.md). Do not install these patches globally.

Legacy v0.1 `src/run.ts`, `src/tools.ts`, and its old SDK tests remain as historical regression coverage but are **not** the main `omo-mini` command; new work should use upstream native tools and sessions. CI runs frozen install, typecheck, tests and build on Windows and Ubuntu without a local model. A real loaded-model check is available with `bun benchmarks/native-live.ts` (public prompts only; disposable state; prints structured evidence). Do not use private clipboard material as QA input.
